# 附录 E · 决策记录（固化自草案 D1–D16 与各裁决表）

> 草案删除后，本附录是"为什么这样设计"的唯一出处。G2 会把其中适合公开的部分并入正式文档。
> 每条格式：结论 —— 依据 —— 落在哪。

## E.1 工程与模块

| 结论 | 依据 | 落点 |
| --- | --- | --- |
| 模块交付为**单个自包含文件** `<name>.vbmodule.js`，宿主不引用源码 | 构建简单、分发只需一个文件 | 附录 D.2 |
| 模块**在 Project File 声明**，不随 VSIX 发布 | 项目自己决定用哪些模块 | D.1 |
| 源码放仓库内独立 `Modules/`，其他项目可整目录拷走 | 一套源码、多种工程 | D.6 |
| MCP 与 VS Code 加载**同一份** bundle | 行为一致、只维护一套 | D.6 |
| SDK 以主仓库为准，打包成 `.tgz` 放入 `Modules/Sdk/` 只读使用 | 避免模块反向依赖主仓库源码 | D.2、D.6 |
| MCP 模块授权用 `VISUALBRIDGE_MODULES_ENABLED` + 工作区路径边界 | 无 GUI 信任模型可用 | D.6 |
| Project File 升到 `formatVersion: 2`，`modules` 必填，`tableLayout` 迁入 Table 模块 `options` | 领域配置归领域模块 | D.1 |
| 同一 editor/分类冲突按 `modules` 顺序保留第一个并报 `module.editorConflict` | 可预测、不静默覆盖 | D.1、D.4 |
| 不做模块市场/签名/远程下载；不做热替换；不做跨 `apiVersion` 兼容 | 第一版只解决"可拆可加载" | `Doc/ModuleSystem.md` §8 第 7 条 |
| 不做模块 overlay（同分类替换展示）；先用 `modules[].options.debug` 定制 | 避免加载顺序语义反转 | 附录 D.4、Backlog |

## E.2 调试契约

| 结论 | 依据 | 落点 |
| --- | --- | --- |
| 调试契约用 **C# 接口 + 生成器**，不再向协议里加字符串 domain/kind | 字符串契约会持续膨胀，调用方要记字符串 | 附录 B.5 |
| 业务像 `Debug.Log` 一样调用，不判断连接、不处理异常 | 插桩成本最低 | B.2 |
| `Create` / `Finish` 显式管理实例生命周期，`instanceId` 存 `HashSet` | 需要明确的开始/结束，供 UI 分组 | B.3 |
| 分类**只有字符串、没有数字号** | 分类由实例携带，二进制头不需要分类 | A.4 |
| 实例描述（`resName`/`debugInfo`）发送后**不保留**在 Unity 侧 | 省内存，服务端只做实例/分类筛选 | B.3、A.9 |
| `contractHash` 全局一致；不一致时**保留连接**、数据面降级 JSON | 断连代价高于降级 | A.3 |
| 二进制载荷只写非默认值（稀疏） | 长会话省带宽 | A.4 |
| 查询两段超时（排队 2 s / 执行 3 s）、并发 8、主线程每帧最多 1 条 | 不卡帧、可预测 | B.6 |
| 断点/单步/求值、DAP **不做** | 超出"事件观察 + 轻量查询"的范围 | —— |

## E.3 传输与连接

| 结论 | 依据 | 落点 |
| --- | --- | --- |
| 同一时刻**一条连接**，VS Code 与 Unity 一对一，所有实例共享 | 避免多连接状态同步 | A.2 |
| 回环/局域网 **TCP**，删除命名管道 | 管道不跨平台、Mono 无读超时 | A.1 |
| 6 字节头 + 通道位 + CRC16（只校验头） | 分帧便宜，误连能在首包断开 | A.1 |
| 编辑器消息与调试消息**并入同一协议**，只有一个 `protocolVersion` | 一次握手、一条连接 | A.2 |
| 连接方向按环境翻转：Editor 模式 VS Code 监听、Unity 拨号；Player 反向 | 编辑器里 VS Code 常驻、Player 里 Unity 常驻 | A.8 |
| Domain Reload 用"自动重连 + 会话续接（15 s 宽限）"，不做连接持久化 | 托管 socket 必然销毁 | A.8 |
| 局域网**无认证**（Player），token 只用于编辑器模式 | 已知风险，接受 | A.3、A.8 |
| 不做 WebSocket；传输绑定保留可替换 | v1 只做直连 | —— |
| debug 总开关可由 VS Code 在编辑器模式切换，存 `EditorPrefs`；Player 只由配置决定 | 调试期不想回 Unity 点按钮 | A.8 |

## E.4 展示与消费

| 结论 | 依据 | 落点 |
| --- | --- | --- |
| 每条记录**恰好一个主消费者**，同时**总进**通用视图（观察者） | 既有语义聚合，又能兜底 | 附录 C.5 |
| 容量按字节（每实例 32 MB / 全局 128 MB），条数只是辅助上限 | 字节才是内存真相 | C.4 |
| 实例上限 32，按**最后活跃时间**淘汰；只抑制数据帧 | 控制帧丢了会让实例停在 live | C.4 |
| 回放游标淘汰后夹取并标 `partial`，不重置 | 用户视角连续 | C.4 |
| 录制在**解码之前**、只录业务帧、内嵌契约快照 | 录制要能脱离工作区回看 | C.6 |
| 项目级展示定制走 `modules[].options.debug`，不做代码级替换 | 一个扩展机制即可 | D.4 |
| 契约唯一来源是 Unity 生成产物（`ArtifactsRoot`），客户端自动定位；`contractDirectories` 只补充 | 开箱可用，避免手填 | C.8 |
| 展示由模块 `debug` facet 提供，数据面（接收/解码/存储/回放/录制）归宿主 | 解码与存储只写一份 | D.4 |

## E.5 已否决/延后的备选

| 备选 | 决定 | 原因 |
| --- | --- | --- |
| 项目级调试插件（`vb-debug-plugin.json`） | 否决，改为模块 `debug` facet | 两套扩展机制、两套授权与契约来源 |
| 客户端挂起表 32 | 改为 8 | 与服务端并发一致，避免排队后必失败 |
| 客户端查询超时 5 s | 改为 8 s | 服务端最坏 2 s + 3 s，需留网络余量 |
| 槽位空闲表复用 | 否决，改单调递增 | 槽位复用 + 在途帧会归错实例 |
| 控制/数据队列各自写出 | 否决，改单写序列 + 屏障 | `Finish` 可能越过在途数据帧 |
| 模块自带上限 1024 vs 客户端 32 不一致不管 | 保留两级上限，但只抑制数据帧 | 业务侧不被硬限，客户端诚实降级 |
